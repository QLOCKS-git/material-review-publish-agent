# 01 需求与成功标准

## 用户与目标

面向内容团队，对待处理素材进行审核并生成可确认、无冲突的发布排期草稿。
输入为素材 ID/元数据、用户时间要求、已有排期和审核规则。输出逐项包含审核状态、风险原因、原时间、建议时段、待确认事项及草稿保存结果。

## 范围

提供 CLI、合成本地资料和四种业务工具。真实模型通过读取资料、规则检查、时段查询与保存工具完成动作/观察循环。
另提供明确标记的确定性 Mock，用于无模型环境复现流程。无界面、真实发布、多 Agent 或生产级 Runtime。

## 约束

- 不得把草稿声称为已发布。
- 未经用户同意，不得覆盖硬性发布时间或将替代时段标为已确认。
- 资料不足、风险阻断、保存失败必须有明确结果。
- 相同请求重复保存只能形成一份草稿。
- 时段占用变化后重提，需要重新查询及调整原草稿。
- 模型每轮选择动作，工具执行后回传观察，模型调整下一步或结束。
- 设置执行上限，超限明确返回未完成。
- Trace 记录实际工具参数、返回摘要、后续动作及一句决策依据，不保存模型内部思维过程。

## 验收点

| 编号 | 场景 | 成功标准 |
| --- | --- | --- |
| A1 | 正常排期 | 审核通过，原时段可用，实际保存一份草稿 |
| A2 | 素材资料缺失 | 补查后仍缺失时请求资料，不编造信息或保存排期 |
| A3 | 规则风险 | 记录风险及阻断/待确认状态，无法绕过审核保存 |
| A4 | 时段冲突 | 查询替代时间，保留原要求并标记待确认 |
| A5 | 重复提交 | 同一草稿 ID、单条记录；占用变化后更新建议而非增加草稿 |
| A6 | 保存失败 | 明确未保存，不产生虚假草稿 ID 或成功状态 |
| A7 | 执行上限 | 达到上限停止并返回 INCOMPLETE |
| A8 | 不同路径 | 真实模型根据不同工具结果选择补查、阻断、替代或保存，提供至少两条实际路径 |

数据均为合成资料。默认时区 Asia/Shanghai，时间输入必须显式包含时区。
