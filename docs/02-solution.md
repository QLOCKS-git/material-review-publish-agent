# 02 方案与取舍

## 模块

- domain：校验输入和动作，规范时间，计算不可变要求指纹。
- models：本地 llama.cpp / Ollama 的 Qwen 适配器及独立 Mock。应用不依赖 Agent 框架。
- runner：有上限的模型 -> 工具 -> 观察循环和可信结果汇总。
- tools：素材读取、规则检查、时段查询、保存草稿及业务前置检查。
- store：SQLite 持久化、事务、防重和时段唯一约束。
- evaluation：执行合成场景，将实际结果、Trace 和草稿快照写入 examples。

## 动态决策

用户请求只提供素材编号和时间约束，不包含预期答案或 world 全量数据。
每轮调用真实模型，输出 action、material_id、include_supplement、proposed_at 和 decision_basis。程序校验后执行工具，将真实返回写入消息，再次调用模型。
模型可选择补查资料、重新核验、查询时段、建议替代、保存或结束。没有按场景编号硬编码真实模式执行路线。

工具权限和保存前置条件属于确定性执行骨架。审核、时段和用户同意不能由模型自报；工具以实际资料及 request 为准。
只有 MockModel 使用固定条件分支，明确用于流程测试，不作为 ReAct 效果证据。

## 确认边界

原始 requested_at 和 hard_time 来自用户输入并保留。
替代时段未经 approved_alternatives 同意时，保存为 PENDING。规则中的确认项需出现在 approved_risks，才能解除对应待确认标记。
工具没有发布能力。最终 published、草稿 ID 和保存状态从工具结果推导，不直接采用模型的成功声明。

## 防重与占用变化

唯一键为 request_id/material_id。原始时间、渠道、硬性约束形成不可变指纹；复用请求编号改变这些字段时拒绝保存。
用户补充确认不覆盖原始时间，可更新同一草稿。
查询会排除其他已保存草稿及已有排期，但排除当前草稿自身，便于原记录重新规划。
保存采用 BEGIN IMMEDIATE 事务和 channel/proposed_at 唯一约束。保存前后核对资料版本；变化时返回可观察错误，由模型选择重新读取/核验，而非固定自动重试。
跨次运行遇到新的占用时，保存更新原行，保留草稿 ID，避免幂等缓存掩盖已冲突的建议。

## 技术取舍

Python 标准库降低安装成本，SQLite 支持本地复现和并发唯一性验证；llama.cpp 提供本地模型推理及 JSON Schema 约束输出（固定提交版本见 README），Ollama 作为可选接口适配。
结构化输出限定动作格式，并将 material_id 枚举限制为本次请求的素材编号，不预先选择工具或执行路线。模型不可用时明确失败，不静默降级。
采用单 Agent 和 CLI，避免界面、外部服务和复杂运行时挤占核心决策与验证范围。
